# Building & Launching Complete ROS 2 Packages

**Estimated Reading Time**: 10 minutes
**Prerequisites**: ROS 2 Core Concepts
**Difficulty**: Beginner

## Introduction

ROS 2 packages are containers for your robot code. Think of them as folders. These folders hold everything your robot needs. They contain source code, configuration files, and launch scripts. In this chapter, you'll learn how to create and manage packages.

By the end, you'll be able to build your own packages. You'll also learn to launch multiple nodes together. This is essential for robot systems.

## What is a ROS 2 Package?

A package is the basic unit of organization in ROS 2. It groups related functionality together. For example, you might have one package for perception. You might have another for navigation.

Each package contains:
- Source code (Python or C++)
- Configuration files
- Launch files
- Package metadata

### Example 1: Real-World Package Structure

**Type**: Analogy

**Context**: Imagine you're organizing a kitchen. You don't throw everything into one drawer. Instead, you organize items into logical groups.

**Explanation**: ROS 2 packages work the same way. Your navigation code goes in a "navigation" package. Your camera code goes in a "vision" package. This makes finding code much easier.

**Takeaway**: Packages help you organize robot code into logical, reusable units.

## Package Structure

A typical ROS 2 package looks like this:

```text
my_robot_package/
├── package.xml          # Package metadata
├── setup.py             # Python package setup
├── setup.cfg            # Configuration
├── my_robot_package/    # Python source code
│   ├── __init__.py
│   └── my_node.py
├── launch/              # Launch files
│   └── my_launch.py
├── config/              # Configuration files
│   └── params.yaml
└── resource/            # Package marker
    └── my_robot_package
```

Each file has a specific purpose:
- **package.xml**: Describes your package and its dependencies
- **setup.py**: Tells Python how to install your package
- **Source files**: Your actual robot code
- **Launch files**: Scripts to start multiple nodes at once

## Creating a New Package

Use the ROS 2 command-line tool to create packages:

```bash
cd ~/ros2_ws/src
ros2 pkg create --build-type ament_python my_robot_package
```

This command creates a new package. It includes all the necessary files. The `--build-type ament_python` flag specifies Python.

:::tip Quick Start
Always create packages inside your workspace's `src` directory. This keeps your projects organized.
:::

## Package Configuration Files

### package.xml

This file describes your package:

```xml title="package.xml"
<?xml version="1.0"?>
<package format="3">
  <name>my_robot_package</name>
  <version>0.0.1</version>
  <description>My robot control package</description>
  <maintainer email="you@example.com">Your Name</maintainer>
  <license>Apache License 2.0</license>

  <depend>rclpy</depend>
  <depend>std_msgs</depend>

  <export>
    <build_type>ament_python</build_type>
  </export>
</package>
```

The `<depend>` tags list other packages your code needs. ROS 2 uses this to install dependencies.

### setup.py

This file tells Python how to install your package:

```python title="setup.py"
# Library: setuptools v65.5.0
# Last updated: 2025-12-05
# Tested on: ROS 2 Humble, Python 3.10

from setuptools import setup

package_name = 'my_robot_package'

setup(
    name=package_name,
    version='0.0.1',
    packages=[package_name],
    install_requires=['setuptools'],
    zip_safe=True,
    maintainer='Your Name',
    maintainer_email='you@example.com',
    description='My robot control package',
    license='Apache License 2.0',
    entry_points={
        'console_scripts': [
            'my_node = my_robot_package.my_node:main',
        ],
    },
)
```

The `entry_points` section is important. It creates commands you can run from the terminal.

## Building Your Package

After creating your package, you need to build it:

```bash
cd ~/ros2_ws
colcon build --packages-select my_robot_package
```

This command compiles your code. It prepares it for use. The `--packages-select` flag builds only your package. This is faster.

After building, source the workspace:

```bash
source install/setup.bash
```

This command tells your terminal where to find your newly built package.

:::note Build Directory
The build process creates three directories. These are `build`, `install`, and `log`. They contain compiled code and installation files.
:::

### Example 2: The Build Process

**Type**: Analogy

**Context**: Building software is like preparing food. You can't throw raw ingredients into a pot.

**Explanation**: The `colcon build` command processes your code. It checks dependencies. It creates executable files. Just like prep work makes cooking easier, building makes your code ready to run.

**Takeaway**: Always build after making changes to your code. The build step prepares everything to run correctly.

## Launch Files

Launch files let you start multiple nodes with one command. This is useful. Robots need many nodes running together.

### Creating a Launch File

```python title="launch/my_launch.py"
# Library: launch v1.0.4, launch_ros v0.19.4
# Last updated: 2025-12-05
# Tested on: ROS 2 Humble, Python 3.10

from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(
            package='my_robot_package',
            executable='my_node',
            name='my_node_1',
            output='screen'
        ),
        Node(
            package='my_robot_package',
            executable='my_node',
            name='my_node_2',
            output='screen',
            parameters=[{'speed': 1.5}]
        ),
    ])
```

This launch file starts two nodes. Notice the second node gets a parameter. Launch files make it easy to configure nodes.

### Running a Launch File

```bash
ros2 launch my_robot_package my_launch.py
```

This command starts all nodes defined in the launch file. You'll see output from both nodes in your terminal.

:::tip Parameter Files
You can load parameters from YAML files. This keeps configuration separate from code. It makes things easier to modify.
:::

## Testing Your Package

Always test your package after building:

```bash
# List packages to verify installation
ros2 pkg list | grep my_robot_package

# Check if executables are available
ros2 pkg executables my_robot_package

# Run a node
ros2 run my_robot_package my_node
```

If these commands work, your package is correctly installed.

## Common Issues and Solutions

### Issue: Package Not Found

**Problem**: `ros2 pkg list` doesn't show your package.

**Solution**:
1. Make sure you ran `colcon build`
2. Source the workspace: `source install/setup.bash`
3. Check `package.xml` has correct package name

### Issue: Executable Not Found

**Problem**: `ros2 run` says your node doesn't exist.

**Solution**:
1. Check `setup.py` entry_points section
2. Rebuild: `colcon build --packages-select my_robot_package`
3. Source again: `source install/setup.bash`
