## Understanding the Visualization Pipeline

### The ROS 2 Visualization Stack

To visualize our walking humanoid, we need three components working together:

1. **URDF Model** → Defines the robot's structure (already done!)
2. **Joint States** → Provides current joint positions (your gait publisher!)
3. **Robot State Publisher** → Transforms joint states into 3D poses
4. **RViz** → Visualizes the robot in 3D

Here's the data flow:

```
GaitPublisher → /joint_states → RobotStatePublisher → /tf → RViz
```

:::info What is robot_state_publisher?
`robot_state_publisher` subscribes to `/joint_states`, reads your URDF, and publishes transformations (`/tf`) that represent where each link is in 3D space. This is what makes your robot model move in RViz!
:::

## Step 1: Create the Complete Launch File

Let's create a launch file that brings everything together:

```python title="launch/display_walking.launch.py"
#!/usr/bin/env python3
"""
Complete launch file for visualizing walking humanoid in RViz.

This launch file starts:
1. robot_state_publisher (with URDF)
2. gait_publisher_node (joint trajectory generator)
3. RViz (with custom configuration)
"""

import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration, Command
from launch_ros.actions import Node


def generate_launch_description():
    """Generate the launch description for walking visualization."""

    # Get package directories
    pkg_share = get_package_share_directory('gait_publisher')

    # File paths
    urdf_file = os.path.join(pkg_share, 'urdf', 'simple_humanoid.urdf')
    rviz_config_file = os.path.join(pkg_share, 'config', 'walking_viz.rviz')
    params_file = os.path.join(pkg_share, 'config', 'gait_params.yaml')

    # Declare launch arguments
    use_sim_time_arg = DeclareLaunchArgument(
        'use_sim_time',
        default_value='false',
        description='Use simulation time'
    )

    # Read URDF file
    with open(urdf_file, 'r') as infp:
        robot_description = infp.read()

    # Robot State Publisher Node
    # This node publishes the robot's state based on URDF and joint states
    robot_state_publisher_node = Node(
        package='robot_state_publisher',
        executable='robot_state_publisher',
        name='robot_state_publisher',
        output='screen',
        parameters=[{
            'robot_description': robot_description,
            'use_sim_time': LaunchConfiguration('use_sim_time')
        }]
    )

    # Gait Publisher Node
    # This node generates and publishes walking joint trajectories
    gait_publisher_node = Node(
        package='gait_publisher',
        executable='gait_publisher_node',
        name='gait_publisher',
        output='screen',
        parameters=[params_file]
    )

    # RViz Node
    # Visualization tool
    rviz_node = Node(
        package='rviz2',
        executable='rviz2',
        name='rviz2',
        output='screen',
        arguments=['-d', rviz_config_file] if os.path.exists(rviz_config_file) else []
    )

    return LaunchDescription([
        use_sim_time_arg,
        robot_state_publisher_node,
        gait_publisher_node,
        rviz_node,
    ])
```

## Step 4: What You Should See

When RViz opens, you should see:

### Initial View
- **Grid**: A reference grid on the floor
- **Robot model**: Your humanoid standing upright
- **TF frames**: Coordinate frames for each link

### Walking Motion
Within a few seconds, you should see:
- ✅ **Legs alternating**: Left forward when right is back
- ✅ **Knees bending**: During swing phase (leg forward motion)
- ✅ **Smooth motion**: No jerky or discontinuous movements
- ✅ **Periodic pattern**: Motion repeats every 2 seconds (at 0.5 Hz)

:::tip What to Look For
Watch the feet! You should see them lifting off the ground during swing and staying relatively stationary during stance. The motion should look like walking in place.
:::

- **Top**: See leg positions from above
- **Isometric**: 45° angle showing 3D motion

## Step 7: Experimenting with Parameters

Try different gait styles! Edit `config/gait_params.yaml`:

### Fast Walk
```yaml
gait_publisher:
  ros__parameters:
    step_frequency: 0.8      # Faster steps
    step_height: 0.06        # Lower steps
    stride_length: 0.20      # Longer strides
```

### Slow March
```yaml
gait_publisher:
  ros__parameters:
    step_frequency: 0.3      # Slower steps
    step_height: 0.15        # High knee lift
    stride_length: 0.08      # Short strides
```

### Cautious Walk
```yaml
gait_publisher:
  ros__parameters:
    step_frequency: 0.4
    step_height: 0.04        # Barely lift feet
    stride_length: 0.10
```

## Step 8: Debugging Common Issues

### Issue: Robot doesn't move in RViz

**Check 1**: Verify joint states are publishing:
```bash
ros2 topic hz /joint_states
```

**Check 2**: Verify robot_state_publisher is running:
```bash
ros2 node list
```

**Check 3**: Check for TF data:
```bash
ros2 run tf2_tools view_frames
```

### Issue: Robot parts are disconnected or distorted

**Problem**: URDF joint limits may be exceeded

**Solution**: Check your gait parameters are reasonable:
```bash
ros2 param get /gait_publisher step_height
ros2 param get /gait_publisher stride_length
```

Reduce values if needed.

### Issue: RViz shows errors about transforms

**Problem**: TF tree might be incomplete

**Solution**: Check TF tree:
```bash
ros2 run tf2_tools view_frames
evince frames.pdf  # or open frames.pdf
```

Verify all joints are connected from base_link.

### Issue: Motion looks jerky or stuttering

**Check 1**: Verify 50 Hz publishing:
```bash
ros2 topic hz /joint_states
```

**Check 2**: Check CPU usage:
```bash
top
```

If CPU is maxed, reduce publish frequency:
```yaml
publish_frequency: 25.0  # Lower frequency
```
