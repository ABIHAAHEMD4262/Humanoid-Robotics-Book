# Full Humanoid URDF → SDF Conversion

Converting robot models from URDF (Unified Robot Description Format) to SDF (Simulation Description Format) is essential for using robots in Gazebo simulation.

## Why Convert from URDF to SDF?

- **URDF**: ROS-native format, great for robot description
- **SDF**: Gazebo-native format, more flexible for simulation

SDF provides:
- Better physics simulation capabilities
- Native Gazebo plugin support
- More detailed sensor and material descriptions
- World and environment modeling

## Understanding URDF

URDF is an XML format that describes a robot's:
- **Links**: Rigid bodies (e.g., torso, arms, legs)
- **Joints**: Connections between links (revolute, prismatic, fixed)
- **Visual Elements**: Geometry for visualization
- **Collision Elements**: Simplified geometry for physics
- **Inertial Properties**: Mass, center of mass, inertia tensors

### Sample Humanoid URDF Snippet

```xml
<?xml version="1.0"?>
<robot name="humanoid">
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.3 0.2 0.4"/>
      </geometry>
      <material name="blue">
        <color rgba="0 0 0.8 1"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <box size="0.3 0.2 0.4"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="5.0"/>
      <inertia ixx="0.1" ixy="0" ixz="0" iyy="0.1" iyz="0" izz="0.1"/>
    </inertial>
  </link>

  <link name="left_leg"/>

  <joint name="left_hip" type="revolute">
    <parent link="base_link"/>
    <child link="left_leg"/>
    <origin xyz="0 0.1 -0.2" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit effort="100" lower="-1.57" upper="1.57" velocity="2.0"/>
  </joint>
</robot>
```

## Conversion Methods

### Method 1: Using gz sdf Command

The simplest method uses Gazebo's built-in converter:

```bash
gz sdf -p your_robot.urdf > your_robot.sdf
```

This automatically converts URDF to SDF format.

### Method 2: Using ROS 2 xacro + Conversion

If your robot uses Xacro (parametric URDF):

```bash
# First, process xacro to URDF
ros2 run xacro xacro your_robot.urdf.xacro > your_robot.urdf

# Then convert to SDF
gz sdf -p your_robot.urdf > your_robot.sdf
```

### Method 3: Manual Conversion

For complex robots, manual conversion gives you more control.

## Key Conversion Considerations

### 1. Inertial Properties

Ensure accurate inertial properties for stable simulation:

```xml
<!-- URDF -->
<inertial>
  <mass value="5.0"/>
  <inertia ixx="0.1" ixy="0" ixz="0" iyy="0.1" iyz="0" izz="0.1"/>
</inertial>

<!-- SDF equivalent -->
<inertial>
  <mass>5.0</mass>
  <inertia>
    <ixx>0.1</ixx>
    <ixy>0</ixy>
    <ixz>0</ixz>
    <iyy>0.1</iyy>
    <iyz>0</iyz>
    <izz>0.1</izz>
  </inertia>
</inertial>
```

### 2. Joint Limits and Dynamics

Convert joint properties accurately:

```xml
<!-- URDF -->
<joint name="knee" type="revolute">
  <limit effort="100" lower="-2.0" upper="0" velocity="2.0"/>
  <dynamics damping="0.7" friction="0.0"/>
</joint>

<!-- SDF equivalent -->
<joint name="knee" type="revolute">
  <axis>
    <xyz>0 1 0</xyz>
    <limit>
      <lower>-2.0</lower>
      <upper>0</upper>
      <effort>100</effort>
      <velocity>2.0</velocity>
    </limit>
    <dynamics>
      <damping>0.7</damping>
      <friction>0.0</friction>
    </dynamics>
  </axis>
</joint>
```

### 3. Collision Geometry Simplification

Simplified collision geometry improves performance:

```xml
<collision name="torso_collision">
  <geometry>
    <box>
      <size>0.3 0.2 0.4</size>
    </box>
  </geometry>
</collision>
```

## Testing Your Converted Model

Load your SDF model in Gazebo:

```bash
gz sim -v 4 your_robot.sdf
```

Check for:
- Correct link positions
- Proper joint behavior
- Stable physics simulation
- No collision issues

## Common Conversion Issues

### Issue: Robot Falls Through Ground
**Solution**: Check collision geometry and contact parameters

### Issue: Joints Are Too Stiff/Loose
**Solution**: Tune joint damping and friction values

### Issue: Robot Explodes on Startup
**Solution**: Verify inertial properties, reduce initial velocities

### Issue: Meshes Don't Load
**Solution**: Ensure mesh paths are correct, use relative paths or ROS package URIs

## Automation Script

Create a conversion script for batch processing:

```python
#!/usr/bin/env python3
import subprocess
import sys

def convert_urdf_to_sdf(urdf_file, sdf_file):
    """Convert URDF to SDF using gz sdf command"""
    try:
        result = subprocess.run(
            ['gz', 'sdf', '-p', urdf_file],
            capture_output=True,
            text=True,
            check=True
        )

        with open(sdf_file, 'w') as f:
            f.write(result.stdout)

        print(f"Successfully converted {urdf_file} to {sdf_file}")
    except subprocess.CalledProcessError as e:
        print(f"Error converting {urdf_file}: {e.stderr}")
        sys.exit(1)

if __name__ == "__main__":
    if len(sys.argv) != 3:
        print("Usage: convert_urdf_sdf.py <input.urdf> <output.sdf>")
        sys.exit(1)

    convert_urdf_to_sdf(sys.argv[1], sys.argv[2])
```
